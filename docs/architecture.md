# 架构与信任边界

## 请求路径

```text
Lark 出站长连接
  -> 身份、群聊和 @ 校验
  -> 持久化事件去重 + 有界请求队列
  -> 按会话键串行的 Pi Agent
  -> beforeToolCall 默认拒绝策略
  -> 五个只读工具
  -> 结构化、截断、脱敏结果
  -> afterToolCall 审计
  -> Lark 回复
```

私聊会话键由 `open_id + chat_id` 的不可逆摘要构成；群聊按 `chat_id` 隔离，但每次调用仍保留当前发言人的角色和身份摘要。同一会话串行处理，不同会话可在全局上限内并发。

Pi 会话仓库按请求打开并在回答持久化后立即关闭，避免历史会话永久保留 writer lease、定时心跳和 Agent 内存。恢复会话时只读取最近 80 条消息，并丢弃因窗口边界产生的孤立工具结果；送入模型前同时按 token 估算与 UTF-8 字节预算裁剪，并把工具调用及其结果作为不可拆分单元。单个工具结果进入模型前还有 16 KiB 上限。完整消息仍保存在 Pi SQLite，裁剪不影响审计记录。

## 模块

- `src/lark`：长连接适配、事件归一化、快速接收和回复。
- `src/agent`：Pi Agent 生命周期、上下文裁剪、工具事件和进度。
- `src/tools`：固定命令适配器、严格 Schema、五个只读工具。
- `src/policy`：用户/群白名单、角色和默认拒绝工具策略。
- `src/storage`：业务 SQLite、Pi 会话 SQLite 和迁移。
- `src/monitoring`：存活/就绪端点。

业务状态和 Pi 会话使用不同数据库，以免第三方后端迁移与业务 Schema 耦合。业务数据库采用 WAL、外键、短同步事务，并在启动时将遗留的审计 `started`、入站 `received/processing` 与任务 `running` 状态恢复为失败或中断。就绪探针每次执行轻量读取，但实际可写性探针最多每五分钟提交一次，以减少 NAS 上的持久写放大。

入站事件采用保守的 at-most-once 语义：一旦持久认领，同一事件 ID 不会自动重放。服务在认领后崩溃可能导致该只读请求需要用户重新发送，但不会因自动重放造成重复回复；进入有副作用的 Phase 2 前必须升级为独立的持久执行状态机。

## 系统命令边界

模型只能选择注册工具，不能提供可执行文件或参数。工具内部使用绝对路径、固定参数数组、`shell: false`、最小环境、超时、输出字节上限和全局并发上限。原始 stderr 不进入模型或审计。

Wi-Fi 工具固定读取配置的接口（默认 `wlp2s0`），磁盘工具固定执行 `df`。Docker 工具只尝试只读 `docker ps`；生产账户不得加入 `docker` 组，因此在独立只读代理尚未部署时它会安全地报告不可用。

## 暂不包含

审批卡片、`restart_container`、`run_backup`、主动监控调度器和 Wi-Fi watchdog 属于后续阶段。数据库已预留审批、告警和任务表，但这些动作没有注册到 Agent。
